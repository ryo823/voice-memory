## 評価セット v2

- メモリ120件（既存40件 + 追加80件、すべて合成）: `tests/fixtures/search_eval.json`。既存40件・既存クエリ20件は無変更
- クエリ64件: exact 6 / short 4 / tag 4 / paraphrase 15 / temporal 10 / person_event 10 / composite 5 / no_match 10
- 追加メモリには「キーワードは重なるが人・日付・意味が違う」紛らわしいペアを含める（例: 田中さん(同僚) と 田中歯科、佐藤部長 と 取引先の佐藤さん、息子のピアノ発表会 と 娘のバレエの発表会、腰痛の初診 と 再発）
- 既存クエリの正解が増えたメモリで崩れないよう、追加メモリは既存クエリ（Whisper・運動・学校・買い物・健康 など）に該当する語を避けている。実際に既存20件の結果は v1 と一致
- temporal の「先月」は `as_of`（2026-11-20）を基準にした10月を指す
- 指標: Recall@k / MRR。**no_match（relevant=[]）は Recall/MRR の平均から除外**し、1件以上ヒットした割合 = false positive rate で見る

## 観察された弱点

1. **paraphrase / temporal / composite は全滅**（計30件、すべて返却0件）。クエリ全体が空白なしの1語として trigram 照合されるため、言い換え・「九月の前半に」「最初に」などの文脈語を含む自然文は一件も引っかからない。第2週の改善対象はここ。
2. **日付・順序の手がかりは未使用**。`recorded_at` による絞り込み・並べ替え（月指定、最初／最新、〜より前）を検索が解釈しない。
3. **no_match の FPR 0.000 は「良い」とは言えない**。全文一致できないクエリは何も返さないだけで、緩い検索（部分語OR・意味検索）を入れると FPR は上がる。第2週以降はこの指標が悪化していないかを見る。
4. **bm25 は現状で recent と区別がつかない**。メトリクスは全カテゴリで同一。順序が変わったのは複数件ヒットする q19（買い物タグ）と q45（井上さん）だけで、いずれも正解が全件ヒットしているため指標に出ない。ヒット数が少なく、順位の質を測れる問い（複数候補から選ぶもの）が不足している。
5. tag は R@5 が 0.812（q19・q20 は正解8件で上位5件に収まらないため。R@10 は 1.0）で、検索の欠陥ではなく指標の上限。
6. person_event が満点なのは、人名・出来事名が短い語として文面に現れるため。表記ゆれ（「健太」→「弟」、敬称なし等）の問いは未収録。
