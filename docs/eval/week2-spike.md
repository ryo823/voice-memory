# 第2週 埋め込みモデル スパイク

- 実施: 2026-11-28 / raspi5（8GB RAM, CPU のみ）/ onnxruntime 1.31.0 + tokenizers 0.23.3（torch・sentence-transformers は未導入）
- 計測スクリプト: `scripts/spike_embed.py`（モデルは `/tmp` に手動取得、リポジトリには含めない）。生データ: `week2-spike/*.json`
- 対象: 合成フィクスチャ（メモリ120件 = タイトル+要約+本文を連結 / クエリ64件）

## 決定

**Run2 では `ruri-v3-30m`（ONNX int8）を採用する。**

根拠: 両系統とも ONNX で動いたため判断基準「日本語の言い換えペアでの分離が良い方」を適用。ruri は 6ペア全てで正解メモリが無関係メモリの最高値を上回ったが、e5 は「ご近所トラブル」で逆転した（下表）。純ベクトルの paraphrase R@5 も ruri 0.967 に対し e5-small 0.833〜0.900。サイズ・メモリ・速度でも ruri が上回る（int8 で 37MB / RSS 251MB）。

注意（Run2 に引き継ぐ点）:
- 指定の `ruri-small-v2` は公式リポジトリに ONNX が無い（`tokenizer_config.json` のみ）。「ruri-small-v2 系」として、**v3 世代の `cl-nagoya/ruri-v3-30m` を第三者が ONNX 変換した `sirasagi62/ruri-v3-30m-ONNX`** を使った。公式配布ではないため、本番採用時は変換元との出力一致と配布元の信頼性を再確認すること。ライセンスは未確認（本家 ruri-v3 のモデルカードで要確認）。
- 接頭辞は ruri-v3 公式の「1+3」ルールに従い、クエリ `検索クエリ: `、文書 `検索文書: `。e5 は `query: ` / `passage: `。
- **類似度の絶対値では no_match を弾けない**。no_match クエリの最大類似度（0.79〜0.87）が、paraphrase の正解類似度の平均（ruri 0.86）と重なる。Run2 では閾値だけに頼らず、方式Bの語彙一致などとの併用や相対スコアを検討する。

## 言い換えペアのコサイン類似度

クエリ vs 正解メモリ、クエリ vs 無関係メモリ（正解以外の全件）。「分離」= 正解の類似度 − 無関係の平均。「逆転なし」= 正解 > 無関係の最高値。

| クエリ | e5 fp32 分離 | e5 int8 分離 | ruri fp32 分離 | ruri int8 分離 | 逆転なし(e5 / ruri) |
|---|---|---|---|---|---|
| 転居 | 0.055 | 0.060 | 0.063 | 0.063 | ○ / ○ |
| アレルギーの薬 | 0.083 | 0.075 | 0.128 | 0.127 | ○ / ○ |
| パソコン購入 | 0.071 | 0.057 | 0.101 | 0.106 | ○ / ○ |
| ご近所トラブル | 0.033 | 0.023 | 0.089 | 0.093 | **× / ○** |
| 食器を自動で洗う機械 | 0.070 | 0.069 | 0.088 | 0.092 | ○ / ○ |
| ネット回線が遅い | 0.085 | 0.072 | 0.110 | 0.115 | ○ / ○ |
| **平均** | 0.066 | 0.059 | 0.096 | 0.099 | |

どのモデルも「正解 > 無関係の平均」は満たすが、e5 は無関係メモリでも 0.77〜0.80 と全体が高止まりで余裕が小さい。
